# Tutorial 37: Palimpsest analysis (palimpsestr / SEF)

## Introduction

PyArchInit integrates **palimpsestr**, an R library that applies the
**SEF — Stratigraphic Entanglement Field** model for the *probabilistic
decomposition of palimpsests*: it statistically separates the finds of a complex
deposit into latent **phases**, estimating for each stratigraphic unit (US) its
phase membership, its residuality and any **intrusions**.

The **palimpsestr** dialog (the layered-strata icon in the pyArchInit toolbar)
lets you:

- **Fit SEF**: estimate phases and produce vector layers (phases, links) and a
  diagnostics table;
- **Intrusions**: detect chronologically out-of-place finds/US;
- **Narrated report (PDF/DOCX)**: an interpretive report with text, diagnostic
  plots and tables;
- **AI report**: a descriptive report generated by specialised AI agents, in any
  pyArchInit language;
- work on both **SQLite/Spatialite** and **PostgreSQL/PostGIS**;
- use an **absolute chronology** (OxCal calibrated dates) in place of the
  free-text dating.

> Requires palimpsestr **≥ 0.22.0** installed in the R library used by the QGIS
> *Processing R Provider*.

---

## 1. Prerequisites

- **R** installed and the **Processing R Provider** plugin enabled in QGIS.
- R package **palimpsestr ≥ 0.22.0** (and dependencies: `sf`, `DBI`, `RSQLite`;
  `RPostgres` for PostgreSQL).
- For the **PDF/DOCX report**: **pandoc** and a **LaTeX** engine (e.g. TinyTeX).
  If missing, the Markdown `.md` narrative + PNG figures are still produced.
- For the **OxCal chronology**: R package **oxcAAR** and **Java** (the OxCal
  engine is downloaded automatically on first use by
  `oxcAAR::quickSetupOxcal()`).
- For the **AI report**: a configured LLM provider (OpenAI, Anthropic, Ollama or
  LM Studio) via the AI Provider selector.

The R scripts (`.rsx`) are **bundled with the plugin** and installed
automatically when the dialog opens; the *Install/update R scripts* button
reinstalls them manually.

---

## 2. Opening the dialog

1. pyArchInit toolbar → analysis menu → **palimpsestr - Analisi palinsesti**.
2. The dialog shows the active database (SQLite or PostgreSQL) and the
   parameters.

---

## 3. Analysis parameters

| Parameter | Meaning |
|---|---|
| **Number of phases (K)** | how many latent phases to estimate (2–12) |
| **Class model** | `multinomial` (recommended) or `gaussian` (legacy) |
| **Noise / outlier component** | enables intrusion/residuality estimation |
| **Intrusion threshold** | minimum posterior to flag a find as an intrusion |
| **Source** | **Both** / **Materials** / **Pottery** |
| **Site filter** | restrict the analysis to one site (empty = all) |

The **Source** selector is shared by Fit, Intrusions and Report: they all honour
the same finds selection.

---

## 4. Fit SEF and Intrusions

- **Fit SEF model**: runs the decomposition and loads the *SEF phases* layer
  (points coloured by phase) and *SEF links* into the project, plus the
  diagnostics table.
- **Detect intrusions**: loads a point layer carrying `intrusion_prob`,
  `direction` and `intrusion_type`.

---

## 5. Narrated report (PDF/DOCX)

1. Set **Report language** (Italian/English) and **Format** (PDF+DOCX / PDF /
   DOCX).
2. Click **Genera report (PDF/DOCX)**.
3. The **results panel** shows the narrative by reading the `.md` file that is
   **always** written next to the output.
4. The **Open PDF / Open DOCX / Open folder** buttons are enabled according to
   the files actually produced.

> If only the `.md` narrative and figures appear (no PDF/DOCX), pandoc/LaTeX are
> missing: the dialog tries to add them to `PATH` automatically; otherwise
> install them (in R: `tinytex::install_tinytex()`).

---

## 6. PostgreSQL / PostGIS

The analyses also run against the active **PostgreSQL** connection of
pyArchInit, not only SQLite. The dialog automatically converts the connection
URL into a libpq DSN and passes it to the algorithms (the `PG_connection`
parameter); with PostgreSQL active no SQLite file is requested.

---

## 7. Absolute chronology (OxCal)

The optional **`palimpsest_chronology`** table provides **per-US calibrated
dates** (calendar years, BCE negative) that palimpsestr uses **in place of** the
free-text `datazione`.

1. Click **Cronologia assoluta (OxCal)…**.
2. **Create/update table**: creates `palimpsest_chronology` on the active backend
   (SQLite or PostgreSQL), idempotently.
3. **Live calibration**: enter, per US, the radiocarbon dates (BP ± error, lab
   code) and click **Calibra e salva (OxCal)**: an R driver
   (`oxcAAR::oxcalCalibrate` + `palimpsestr::chronology_from_oxcal`) computes the
   calendar intervals and saves them as `start`/`end`.
4. **CSV import**: alternatively, import a pre-calibrated CSV with columns
   `sito, area, us, start, end, lab_code, source`.

Sample data is in `docs/examples/`:
`palimpsest_oxcal_samples_villa_romana.csv` (C14 samples for calibration) and
`palimpsest_chronology_villa_romana.csv` (already-calibrated intervals).

> Once populated, the table is detected **automatically** — no change to the
> algorithms is needed.

---

## 8. AI report (descriptive analysis)

The **Report AI (analisi descrittiva)…** button generates a **descriptive,
didactic** report with a pipeline of **specialised AI agents**:

1. **Methodologist** — explains the choices: the model (multinomial vs
   gaussian), the **K** value and the diagnostic evidence supporting it, the
   noise component and the **threshold**, the finds selection and the OxCal
   chronology use; states limits and caveats.
2. **Analyst** — interprets phases, chronology (with the absolute dates when
   present), residuality/intrusions and spatial pattern.
3. **Editor** — composes a single cohesive report, referencing the figures.

Procedure:

1. Choose the **AI Provider** and model in the selector.
2. Choose the **Report language** (all pyArchInit languages:
   it, en, de, es, fr, pt, ca, ro, el, ar).
3. Click **Genera report AI**: the text appears in real time.
4. Save as **DOCX** (with figures embedded) or **Markdown**.

The report explicitly explains **why** the model, the K and the threshold were
chosen, and interprets the results in an understandable way — ideal for the
excavation report.

## 9. Editing dates, the OxCal plot, PDF, and a note on taf

- **Saved dates are editable**: the *Cronologia assoluta* dialog **loads on
  open** the dates already in `palimpsest_chronology` (*Ricarica dal DB*
  button). You can edit the **start/end** columns by hand and press **Salva
  modifiche (start/end)**, or enter new C14 dates and press *Calibra e salva*.
  Dates **persist** in the database — no need to re-enter them every time.
- **Calibration plot**: after *Calibra e salva*, the **Mostra grafico OxCal** /
  **Esporta grafico (PNG)** buttons show a per-US panel with the probability
  curve, the 95% HPD band and the calendar interval.
- **AI report as PDF**: besides DOCX and Markdown, the AI report can be saved as
  **PDF** (*Salva PDF…* button), with tables and figures embedded.
- **Taphonomic score (taf)**: an **interpretive** value in `[0,1]`
  (0 = fully disturbed/redeposited find, 1 = pristine in situ) that weights
  finds in the estimation. It is **not computed automatically**: the excavator
  assigns it from the depositional context (e.g. 1.0 in-situ deposits; 0.5–0.7
  accumulation/levelling layers; 0.3 clearly redeposited fills).
- **Limitations to keep in mind** (the AI report states them automatically):
  the model assumes **horizontal stratigraphy** (z as a chronological proxy; be
  cautious with cut fills, collapses, terracing); the **resolution is bounded by
  the data**: with US-centroid coordinates and unit-tied dates, a PDI≈1 and zero
  entropy reflect the **recording**, not a perfectly resolved sequence.

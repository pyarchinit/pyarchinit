# Demo, 10 December 2026 — pyArchInit ↔ a StratiGraph room

**Goal:** show, from QGIS, a site going into a room on a StratiGraph node and
coming back — whole records, photos, drawings and excavation plans — and two
people working on the same room.

Slides (English, with screenshots of the rehearsal): the «pyArchInit ↔
StratiGraph — Demo 10 Dec 2026» deck.

**Before the demo**
- pyArchInit **5.19.3-alpha** (s3dgraphy 1.6.0.dev144), EMStudio **1.6.0-dev.155** on the `Stratigraph_00001` branch; QGIS open on a
  database with the sample site («Scavo archeologico», 50 SU, 153 photos,
  57 excavation plans in `pyunitastratigrafiche` / `_usm`).
- A second, **empty** pyArchInit database (SQLite or PostgreSQL) created from
  the configuration window — the "other computer". Its GIS layers are empty
  too.
- The node address and an account on it (CNR test node; the dev-stack
  `https://em.localhost:8443/em` as fallback, started with
  `./fcn-up.sh --source --no-studio` so that its web pages answer). If WP4 has
  imported the `pyarchinit` client, set
  `pyArchInit/stratigraph/client_id = pyarchinit` (see
  `keycloak-client-pyarchinit.md`); otherwise the node's own native client is
  used.
- Pick a new room id (e.g. `demo-10-dicembre`): a room already used carries
  the previous run.
- EMStudio 1.6.0-dev.155 installed (desktop) or its web build, signed in on
  the node: it opens the room from its link, with the photos and, in the
  Space, the excavation plans.
- For part B: TempluMare v3.2 (`EM/TempluMare_v3.2.em.json` with its `EM/`
  folder of proxies and documents) and a third, **empty** database created in
  **EPSG:3844** (TempluMare declares 31700, a deprecated code the QGIS CRS
  selector hides: 3844 is the same Stereo 70, pyArchInit converts without
  moving anything).
- For the check: a copy of the sample site with a few planted errors (a unit
  related to itself, a missing reciprocal, a contradiction, a cycle).

**What to say about what is not there yet**
- Media of finds / pottery / tombs / structures stay local (outside
  StratiGraph's scope for now).
- 3 photos stay in the room: they belong to CON 500, a continuity node the
  export generates and the pull does not recreate.
- «To update» in a compare counts rows the import would rewrite with the same
  values; what matters is «0 real difference(s)».
- EMStudio (dev.155) shows the room's photos and the plans in the Space; it
  marks «12 models do not load»: the reconstruction models of TempluMare's
  `RB` folder, which no record links to, so pyArchInit does not send them.
- Field↔cloud sync between nodes depends on D1–D5 with PSNC.
- Excavation plans follow E.D.'s shape (s3Dgraphy#44), unit ↔ plan through
  the shared GeoJSON resource, as he confirmed.
- The reconstruction's 3D → 2D plans need a database in a metric CRS: with an
  empty database without one, pyArchInit stops and says why, before writing.
- A demo video (≈ 9 min, the presenter's voice) is in
  `~/Movies/pyarchinit-demo/` on the presenter's Mac.

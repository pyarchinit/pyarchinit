# Demo, 10 December 2026 — pyArchInit ↔ a StratiGraph room

**Goal:** show, from QGIS, a site going into a room on the CNR test node and
coming back — whole records, photos, and two people working on the same room.

**Before the demo**
- pyArchInit 5.15.x on the `Stratigraph_00001` branch; QGIS open on a database
  with the sample site («Scavo archeologico», 50 SU, 153 photos).
- A second, **empty** pyArchInit database (SQLite or PostgreSQL) created from
  the configuration window — the "other computer".
- The node address and an account on it (CNR test node; the dev-stack
  `https://em.localhost:8443/em` as fallback). If WP4 has imported the
  `pyarchinit` client, set `pyArchInit/stratigraph/client_id = pyarchinit`
  (see `keycloak-client-pyarchinit.md`); otherwise the node's own native client
  is used.
- Pick a new room id (e.g. `demo-10-dicembre`): a room already used carries
  the previous run.

**The script** (StratiGraph Sync panel → *Send site to a room…*)

| # | Action | What the audience sees | Rehearsal |
|---|---|---|---|
| 1 | *Sign in…* | the node's own login page in the browser; back in QGIS the window shows the user and «may create rooms» | — |
| 2 | *Plan only*, then *Send site* | the plan (files to upload, databases kept as reference), then the operations applied and the photos uploaded; the room link | see below |
| 3 | Switch to the empty database, *Pull from room* | 50 SU with their whole record, periodisation, relations and photos (thumbnails) rebuilt from the room | |
| 4 | Edit a field in the second database, *Compare with room* | «1 field changed here, to send»; the room is read incrementally | |
| 5 | *Send changes* | «1 applied, 1 field» | |
| 6 | Back to the first database, *Compare with room* | «1 field changed in the room, the pull brings it» | |
| 7 | *Pull from room* | the field arrives; a second compare shows nothing to do | |

**Optional, if there is time:** edit the same field on both sides → the
compare shows a **conflict** with both values; *Pull from room* asks before
overwriting.

**What to say about what is not there yet:** media of finds / pottery / tombs
/ structures stay local (outside StratiGraph's scope for now); positive SU
polygons are not sent (s3dgraphy treats their geometry as the 3D proxy); GIS
layers are not written back by the pull; field↔cloud sync between nodes
depends on D1–D5 with PSNC.
